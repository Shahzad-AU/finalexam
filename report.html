Database Design

The Cloudflare D1 database (nexacloud-db) uses a single users table to store all submitted records:

CREATE TABLE IF NOT EXISTS users (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  firstName  TEXT    NOT NULL,
  lastName   TEXT    NOT NULL,
  email      TEXT    UNIQUE NOT NULL,
  department TEXT,
  role       TEXT,
  notes      TEXT,
  created    TEXT    DEFAULT CURRENT_TIMESTAMP
);

The Worker automatically creates this table on first request using CREATE TABLE IF NOT EXISTS, eliminating the need for manual migration steps.

Challenges Encountered

CORS Headers on Worker API — The frontend database page initially received CORS errors when calling the Worker from Pages. Resolved by adding Access-Control-Allow-Origin: * headers to all Worker responses, including the OPTIONS preflight handler.
D1 Binding in wrangler.toml — The database_id must be pasted exactly from the wrangler d1 create output. An incorrect ID causes a binding error at deploy time. Solved by carefully copying the UUID output from the CLI.
GitHub Secrets for Pages Action — The CI/CD workflow requires both CLOUDFLARE_API_TOKEN and CLOUDFLARE_ACCOUNT_ID as repository secrets. Initially the API token was missing the "Cloudflare Pages: Edit" permission — regenerating the token with correct scopes resolved the issue.
D1 Table Auto-Creation — Rather than running manual migrations, the Worker uses CREATE TABLE IF NOT EXISTS on every request to ensure the schema exists. This is acceptable for development but a proper migration strategy (wrangler d1 migrations apply) is recommended for production.

Conclusion

All five tasks were completed successfully. The NexaCloud project demonstrates the full breadth of Cloudflare's developer platform — from serverless edge compute to globally distributed database storage and automated CI/CD pipelines.

The most notable insight from this project is how tightly integrated Cloudflare's services are: a Worker can bind directly to a D1 database with a single line in wrangler.toml, eliminating the boilerplate of traditional cloud database connections. The GitHub Actions integration similarly requires minimal configuration to establish a professional-grade deployment pipeline.

The resulting system is production-ready, globally distributed, and entirely managed through Cloudflare's unified dashboard — with zero server provisioning or infrastructure management required.
